## Context

TaskTracker was a team coursework project: a desktop productivity application built with engineering practices around delivery, deployment, and observability rather than around the task-tracking feature set itself.

## Problem

The project needed to combine an offline-friendly desktop interface with API integration, authentication, repeatable deployment, and monitoring.

## My Role

Within the team, I focused on the software engineering and DevOps side: TypeScript implementation, CI/CD setup, containerization, cloud deployment, and monitoring support.

## Approach

- Built the desktop app using Electron.js and TypeScript.
- Integrated RESTful API behavior and authentication.
- Containerized deployment flow with Docker.
- Automated build and deployment with GitHub Actions.
- Deployed to AWS EC2 and monitored with Prometheus and Grafana.

## Key Decisions

The project emphasized repeatable delivery. Docker and GitHub Actions made the deployment flow more consistent, while monitoring helped connect the application to operational visibility.

## Result

The pipeline automated build, containerization, and deployment end to end: a GitHub Actions workflow built and tested the app, packaged it into a Docker image, and shipped it to AWS EC2, with Prometheus and Grafana in place for runtime monitoring. I don't have a measured before/after baseline for delivery time, so I'm reporting the pipeline itself rather than a speed-up number.

## What I'd Improve

I would add release notes per deployment, document a rollback strategy, include screenshots of the monitoring dashboard, and record an actual baseline so any future delivery-time claim is measured rather than assumed.
